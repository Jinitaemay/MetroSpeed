# MetroSpeed · 地铁测速

基于手机惯性传感器与 GNSS 的轨道交通测速工具，提供稳定放置的连续惯性测速和手持灯光打点测速两种模式。

> **公开状态**：GitHub Release `v1.2.0` 及同名 tag 保存 1.2.0 公开源码；仓库不存在远端 `release/1.2.0` 分支。`fix/post-1.2.0-known-issues` 已作为 GitHub 源码分支推送，但当前没有具备发布资格的 1.2.1 候选，也没有 1.2.1 GitHub Release 或 AppGallery 提交。应用市场版本、公开 Release 与开发分支的功能可能不同。
>
> **系统要求**：HarmonyOS 手机，`compatibleSdkVersion 6.0.0(20)`，`targetSdkVersion 6.1.1(24)`。
>
> **安全提示**：本项目仍处于实验阶段，不能替代列车仪表、执法设备或其他安全关键测速系统。驾驶员不得在行驶过程中操作本应用。

[查看源码](https://github.com/Jinitaemay/MetroSpeed) · [GitHub Releases](https://github.com/Jinitaemay/MetroSpeed/releases)

## 选择测速方式

| 使用条件 | 惯性测速 | 灯光打点测速 |
|---|---|---|
| 工作方式 | 加速度计和陀螺仪连续估算；GNSS 可用时使用速度锚点 | 根据已知灯距和连续打点时间计算速度 |
| 手机放置 | 必须稳定放置 | 由乘客手持操作 |
| 外部参照物 | 不需要 | 需要已知间距的等距灯光 |
| 输出节奏 | 连续更新 | 每次打点后更新 |
| 隧道内使用 | 可以继续估算，但会累积积分漂移 | 取决于灯距是否真实且近似等距 |
| 主要误差 | 重力、主轴和积分漂移 | 灯距误差与点击时机误差 |

两种模式互斥，不自动融合，也不能互相充当真值。

## 快速使用

### 惯性测速

1. 在首页选择 **惯性测速**。
2. 将手机平放在固定、坚硬且不易滑动的位置。
3. 点击 **开始**。首次使用时会出现可选的定位授权；应用会等待授权交互结束，再启动传感器和初始校准。
4. 保持静止约 1.5 秒，随后避免移动手机或改变其朝向。
5. 列车停稳后可点击 **停车校准**，测速结束后点击 **停止**。

拒绝定位不会阻止纯惯性测速，只是不启用 GNSS 速度锚点。

研究记录卡片中的 **GNSS 锚点冻结** 只用于对照实验，普通测速无需操作。它不是入隧/出隧操作步骤，也不是隧道识别或精度增强开关。

### 灯光打点测速

1. 在首页选择 **灯光打点测速**。
2. 输入相邻灯光的实际间距。
3. 在车窗上选定一个固定参照位置。
4. 每盏灯经过该位置时点击打点。
5. 优先观察最近 3～4 个间隔的结果；需要重来时点击 **清空**。

应用同时显示最近 1～4 个间隔的结果：

```text
速度（km/h）= 灯光间距（m）× 间隔数 ÷ 用时（s）× 3.6
```

单次点击时机误差会直接影响结果。灯距变化后，应用会自动清空旧打点，避免混用不同距离的数据。

## 权限、隐私与后台行为

- 惯性测速要求加速度计和校准陀螺仪同时持续提供数据；任一核心传感器启动失败时不会进入测速，运行中断流也会结束本次测速，而不会把缺失陀螺仪当作零角速度继续积分。
- 定位权限是可选项，仅用于 GNSS 速度锚点和研究记录中的定位数据；拒绝后仍可使用纯惯性测速。
- 应用声明 `KEEP_BACKGROUND_RUNNING`，测速或研究记录运行时会申请 LOCATION 类型长时任务。系统不允许或取消长时任务时，应用会结束本次测速与记录并刷新日志。
- 应用不额外声明 `LOCATION_IN_BACKGROUND`，也不声明 `INTERNET` 权限。
- 研究数据只写入应用本机私有目录，不会自动上传。选定导出位置后，应用会在前台保持亮屏，研究记录卡片持续显示复制与落盘进度；导出期间仍可滚动页面查看速度和其他状态，但卡片内控件暂不可操作。完成前仍需保持应用在前台。导出完成后仍可再次导出，开始下一次成功记录时才替换上一条。

## 已知限制

- 纯惯性速度会随时间累积漂移，停车校准只能在停车时重置误差。
- 惯性模式不支持手持；手机位置或朝向变化会破坏重力和主轴假设。
- 当前未适配明显上下坡，坡度可能造成持续速度偏差。
- 弯道、道岔和强振动场景误差可能增大。
- 当前 GNSS 门控依据公开来源和速度精度筛选锚点，尚未额外加入绝对速度、连续跳变和位置龄期上限；有限验证不能覆盖所有设备与场景。
- 灯光模式要求灯距真实且近似等距；未知灯距不能仅凭视频反推出绝对速度。
- 长时间高频采集的功耗、温升、实际回调率和日志体积依设备与系统负载而异。
- 跨设备真实行程、锁屏和长时间后台运行仍需继续验证。
- 导出直接写入系统文件选择器提供的文档位置；受控失败会尝试把未完成目标移入系统回收站，若文档服务拒绝删除则会明确提示手动清理。进程被强制终止或设备掉电仍可能留下不完整目标，本机源记录不会因此删除。

## 工作原理与研究记录

### 惯性估算与 GNSS 锚点

惯性模式从原始加速度中估计重力与列车前进主轴，再对前向运动加速度积分得到速度。当前帧会先进行振动、弯道和低置信度预判，只有通过门控的运动证据才能更新主轴，避免把传导振动方向当成列车前进方向。它不要求持续获得 GNSS 信号，因此在隧道内仍可继续估算，但误差会随时间累积。

应用会检查 GNSS/RTK 位置回调的公开来源、速度精度和速度信号量级。通过当前门控的回调会成为速度锚点，界面速度按以下方式合成：

```text
显示速度 = GNSS 锚点速度 + 当前纯惯性速度 - 锚点时刻纯惯性速度
```

手机处于传导振动或强振动状态时，应用不再仅凭振动状态拒绝 GNSS 锚点。公开回调无法证明系统内部使用的是实时卫星解、VDR 延拓还是其他融合来源。

停车时点击校准，算法会从点击前的历史样本中寻找最稳定的约 1.5 秒窗口，重新估计重力并归零速度。点击后车辆立即起步时，算法会尝试保留校准窗口之后的真实运动增量。

### GNSS 锚点冻结（实验）

开启后，应用会停止刷新 GNSS 锚点并保留最后一个通过当前门控的锚点；这可能增加漂移，不保证提高隧道内测速精度。关闭后旧锚点随即停用，等待新的通过门控的回调。

该开关仅供研究记录中的对照实验使用，不会自动识别隧道，也不能增强系统定位能力。

### 研究记录

研究记录用于离线核查采样率、估算状态、GNSS 锚点和设备运行状况。当前记录格式为 schema v17，包含：

- 六类请求 100 Hz 的传感器：加速度计、陀螺仪、旋转矢量、校准磁场、未校准陀螺仪、未校准磁场；
- GNSS 位置、速度、精度、公开来源和卫星统计；
- 纯惯性速度、显示速度、运动状态、校准状态及测速段标识；
- 每 10 秒一次，以及记录开始和结束时的电池温度与系统热等级。

100 Hz 是请求频率，实际回调率由设备、系统负载和温控策略决定。单独运行研究记录时，若陀螺仪不可用，应用会明确标记降级并继续保存其他可用的原始传感器数据；加速度计持续断流时则会结束记录。JSONL 日志可能很大，建议短时采集并及时导出。

<details>
<summary>估算流程与运行状态</summary>

```text
加速度计驱动估算帧（请求 100 Hz，使用实际时间戳计算 dt）
  → 初始重力校准
  → 加速度限幅与时间等效低通
  → 振动、弯道与低置信度预判
  → 通过门控的前进主轴学习与重力正交化
  → 最终运行时运动状态检测
  → 前向加速度积分
  → 纯惯性速度
  → 可用时叠加 GNSS 锚点增量
```

8 类运行时运动状态的判定优先级为：

```text
CURVE > CONDUCTION_VIB > STRONG_VIB > LOW_CONFIDENCE
      > IDLE > ACCEL > BRAKING > CRUISE
```

`Calibrating` 和 `Stopped` 是另外两种生命周期状态，不计入上述 8 类运行时运动检测。相邻有效样本出现较长缺口时，积分步长会限幅，短时证据窗口、低通状态和未完成的初始校准会从恢复点重新累计，避免跨未观测区间拼接运动证据。

</details>

## 开发与验证

### 技术基线

- 当前开发线：`1.2.1` 源码开发中，当前没有具备发布资格的正式候选
- **算法版本**：`anchor-delta-20260807-r5`
- 研究记录格式：schema v17
- SDK：`compatibleSdkVersion 6.0.0(20)`、`targetSdkVersion 6.1.1(24)`
- 工具：DevEco Studio、HarmonyOS SDK、Python 3.10 或更高版本

仓库不跟踪实际 `build-profile.json5` 和签名材料。首次克隆后复制模板：

```powershell
Copy-Item build-profile.template.json5 build-profile.json5
```

随后在 DevEco Studio 中生成或填写本地调试签名配置。

### 自动化检查

```powershell
python -m unittest discover -s tools -p "test_*.py" -v
python tools/sync_version.py --check
```

### 离线回放

```powershell
# 单条记录
python tools/replay_estimator.py ".\records\sample.jsonl"

# 当前代记录目录
python tools/_baseline_all.py --dir ".\records\current"

# 复现手机 GNSS 锚点合成，并以 -40 ms 偏移评估定位对比
python tools/_baseline_all.py --dir ".\records\current" --anchor-v2 --pure-zero --gnss-lag-ms=-40

# 核查传感器、定位、设备温度与日志完整性
python tools/aux_sensor_location_diag.py ".\records\sample.jsonl"
```

`--allow-truncated-tail` 只应用于确认导出恰好在最后一行写入过程中中断的记录。它不会修改原文件，并会把结果标记为不完整。

## 仓库结构与延伸阅读

- `entry/src/main/ets/`：ArkTS 页面、控制器和测速估算器；
- `tools/`：Python 回放、诊断、版本同步与签名辅助脚本；
- `.trae/documents/investigation_status.md`：当前研究状态与验证边界；
- `.trae/documents/harmonyos_tunnel_positioning_reverse_engineering.md`：HarmonyOS 隧道定位静态研究记录；
- `build-profile.template.json5`：不含实际签名信息的构建配置模板。

应用自身的一维测速算法与 HarmonyOS 私有定位机制研究是两条独立链路；镜像中发现的系统能力不能直接视为 MetroSpeed 已使用的功能。
