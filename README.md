# MetroSpeed · 地铁测速

基于手机惯性传感器与 GNSS 的轨道交通测速工具。

MetroSpeed 提供两种并列的测速方式：

- **惯性测速**：手机稳定放置后，通过加速度计和陀螺仪持续估算速度；GNSS 可用时使用速度锚点抑制漂移。
- **灯光打点测速**：手持手机观察等距灯光，在灯光经过固定参照位置时打点，以距离和时间计算速度。

## 功能概览

### 惯性测速

惯性模式从原始加速度中估计重力与列车前进主轴，再对前向运动加速度积分得到速度。它不要求持续获得 GPS 信号，因此可以在隧道内继续运行。

该模式必须稳定放置手机，建议平放在固定、坚硬且不易滑动的位置。检测到持续手持晃动后，应用会停止惯性测速，并引导切换到灯光打点测速。

### 灯光打点测速

输入相邻灯光的实际间距，在每盏灯经过车窗同一参照位置时点击打点。应用同时显示最近 1～4 个间隔的结果：

```text
速度（km/h）= 灯光间距（m）× 间隔数 ÷ 用时（s）× 3.6
```

单次点击时机误差会直接影响结果，通常应优先参考最近 3～4 个间隔。间距变化后会自动清空旧打点，避免混用不同距离的数据。

### GNSS 锚点

惯性模式运行时，应用会检查 GNSS/RTK 位置回调的来源、速度精度和速度信号量级。通过当前门控的回调会成为速度锚点，界面速度按以下方式合成：

```text
显示速度 = GNSS 锚点速度 + 当前纯惯性速度 - 锚点时刻纯惯性速度
```

手机处于传导振动或强振动状态时，不再仅凭振动状态拒绝 GNSS 锚点。当前门控尚未覆盖所有异常速度、跳变和位置龄期情况，相关过滤仍需继续完善。

### GNSS 锚点冻结（实验）

研究记录卡片中的开关仅用于对照实验。开启后，应用会停止刷新 GNSS 锚点并保留最后一个通过当前门控的锚点；这可能增加漂移，不保证提高隧道内测速精度。关闭后旧锚点随即停用，等待新的通过门控的回调。

该开关不是隧道识别或精度增强开关，也不能判断系统定位服务内部究竟使用了实时卫星解、VDR 延拓还是其他融合来源。

### 停车校准

停车时点击校准，算法会从点击前的历史样本中寻找最稳定的约 1.5 秒窗口，重新估计重力并归零速度。点击后车辆立即起步时，算法会尝试保留校准窗口之后的真实运动增量。

### 研究记录

研究记录用于离线核查采样率、估算状态、GNSS 锚点和设备运行状况。schema v17 记录：

- 六类请求 100 Hz 的传感器：加速度计、陀螺仪、旋转矢量、校准磁场、未校准陀螺仪、未校准磁场；
- GNSS 位置、速度、精度、公开来源和卫星统计；
- 纯惯性速度、显示速度、运动状态、校准状态及测速段标识；
- 每 10 秒一次，以及记录开始和结束时的电池温度与系统热等级。

100 Hz 是请求频率，实际回调率由设备、系统负载和温控策略决定。研究数据仅写入应用本机私有目录，不会自动上传；应用不声明 `INTERNET` 权限。导出后本地记录仍会保留，开始下一次成功记录时才替换上一条。

惯性测速要求加速度计和校准陀螺仪同时可用；任一核心传感器启动失败时不会进入测速。单独运行研究记录时，若陀螺仪不可用，应用会明确标记降级并继续保存其他可用的原始传感器数据。

JSONL 日志体积可能很大，建议短时采集并及时导出。

## 两种模式怎么选

| 使用条件 | 惯性测速 | 灯光打点测速 |
|---|---|---|
| 手机放置 | 必须稳定放置 | 手持操作 |
| 外部参照物 | 不需要 | 需要已知间距的等距灯光 |
| 输出节奏 | 连续更新 | 每次打点后更新 |
| 隧道内使用 | 可以，但存在积分漂移 | 可以，取决于灯光间距是否可靠 |
| 主要误差 | 重力、主轴和积分漂移 | 灯距误差与点击时机误差 |

两种模式互斥，不自动融合，也不能互相充当真值。

## 快速使用

### 惯性测速

1. 在首页选择 **惯性测速**。
2. 首次使用时完成定位授权。
3. 将手机稳定放置，点击 **开始**，保持静止约 1.5 秒。
4. 入隧和出隧时按实际情况切换定位状态。
5. 停稳后可点击 **停车校准**。
6. 测速结束后点击 **停止**。

首次使用时，应用会先等待定位授权交互结束，再启动传感器和初始校准；拒绝定位不会阻止纯惯性测速，只是不启用 GNSS 锚点。

### 灯光打点测速

1. 在首页选择 **灯光打点测速**。
2. 输入相邻灯光的实际间距。
3. 在车窗上选定一个固定参照位置。
4. 每盏灯经过该位置时点击打点。
5. 优先观察最近 3～4 个间隔的结果；需要重来时点击 **清空**。

## 算法概览

```text
加速度计驱动估算帧（请求 100 Hz，使用实际时间戳计算 dt）
  → 初始重力校准
  → 加速度限幅与时间等效低通
  → 前进主轴学习与重力正交化
  → 8 类运行时运动状态检测
  → 前向加速度积分
  → 纯惯性速度
  → 可用时叠加 GNSS 锚点增量
```

运行时运动状态包括：

```text
CURVE > CONDUCTION_VIB > STRONG_VIB > LOW_CONFIDENCE
      > IDLE > ACCEL > BRAKING > CRUISE
```

`Calibrating` 和 `Stopped` 作为另外两种生命周期状态，不计入上述 8 类运行时运动检测。

相邻有效样本出现较长缺口时，积分步长会限幅，短时证据窗口、低通状态和未完成的初始校准会从恢复点重新累计，避免跨未观测区间拼接运动证据。

## 权限与后台行为

应用声明的主要权限包括：

- 加速度计和陀螺仪；
- 精确/模糊定位；
- `KEEP_BACKGROUND_RUNNING`。

测速或研究记录正在运行时，应用退到后台会申请 LOCATION 长时任务。系统允许时继续采集；若长时任务启动失败或被取消，应用会结束本次测速与记录并刷新日志。应用不额外声明 `LOCATION_IN_BACKGROUND`。

## 已知限制

- 纯惯性速度会随时间累积漂移，停车校准只能在停车时重置误差。
- 惯性模式不支持手持；手机位置或朝向发生变化会破坏重力和主轴假设。
- 当前未适配明显上下坡，坡度可能造成持续速度偏差。
- 弯道、道岔和强振动场景误差可能增大。
- 当前 GNSS 门控依据公开来源和速度精度筛选锚点，尚未额外加入绝对速度、连续跳变和位置龄期上限；现有三条当前代记录未观察到原始 GNSS 爆速，但这不等于所有设备与场景都已覆盖。
- 灯光模式要求灯距真实且近似等距；未知灯距不能仅凭视频反推出绝对速度。
- 长时间 100 Hz 采集的功耗、温升和日志体积依设备而异。
- 实车、锁屏和长时间后台运行仍需继续验证。

驾驶员不应在行驶过程中操作本应用。

### 环境

- DevEco Studio 与 HarmonyOS SDK；
- `compatibleSdkVersion 6.0.0(20)`、`targetSdkVersion 6.1.1(24)`；
- Python 3.10 或更高版本，用于离线回放和自动化测试。

仓库不跟踪实际 `build-profile.json5` 和签名材料。首次克隆后复制模板：

```powershell
Copy-Item build-profile.template.json5 build-profile.json5
```

随后在 DevEco Studio 中生成或填写本地调试签名配置。

### 自动化检查

```powershell
python -m unittest discover -s tools -p "test_*.py" -v
python tools/sync_version.py --check
```

### 离线回放

```powershell
# 单条记录
python tools/replay_estimator.py <记录.jsonl>

# 当前代记录目录
python tools/_baseline_all.py --dir <记录目录>

# 复现手机 GNSS 锚点合成，并以 -40 ms 偏移评估定位对比
python tools/_baseline_all.py --dir <记录目录> --anchor-v2 --pure-zero --gnss-lag-ms=-40

# 核查传感器、定位、设备温度与日志完整性
python tools/aux_sensor_location_diag.py <记录.jsonl>
```

`--allow-truncated-tail` 只应用于确认导出恰好在最后一行写入过程中中断的记录。它不会修改原文件，并会把结果标记为不完整。
